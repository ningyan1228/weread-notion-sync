# Notion 书架网站设计方案

目标：基于现有的微信读书 Notion 数据库，做一个漂亮的公开阅读书架网站。

这个方案使用 Notion 作为数据源，不额外引入数据库。微信读书同步仍然由 GitHub Actions 完成，网站只负责读取 Notion 数据并展示。

## 一句话概括

```text
微信读书 -> GitHub Actions -> Notion 数据库 -> 网站后端 API -> 前端书架页面
```

## 为什么用 Notion 当数据库

当前项目已经把微信读书数据同步到了 Notion，包括：

- 书名
- 封面
- 作者
- 分类
- 阅读状态
- 阅读进度
- 阅读时长
- 划线数量
- 想法数量
- 书籍页面内容

所以第一版网站不需要再单独维护数据库。Notion 就是后台，网站从 Notion 读取数据并渲染。

## 核心原则

### 1. Notion Token 不能暴露到浏览器

Notion API 需要 `NOTION_TOKEN`。这个 token 不能写在前端代码里，也不能让浏览器直接请求 Notion。

正确方式：

```text
浏览器 -> 我们自己的 API -> Notion API
```

也就是说，网站需要一个服务端接口，负责安全地读取 Notion。

### 2. 公开网站只展示适合公开的内容

Notion 里可能有私人想法和划线。网站第一版建议只公开书架摘要：

- 书名
- 封面
- 作者
- 分类
- 阅读状态
- 阅读进度
- 阅读时长
- 划线数量
- 想法数量
- 微信读书链接

书籍详情页可以先不公开具体划线内容，或者单独增加配置控制。

### 3. 第一版优先做静态感强、维护成本低的网站

不做登录，不做复杂后台，不做多人系统。

只做一个优雅的个人阅读主页。

## 推荐技术方案

推荐使用：

```text
Next.js + Notion API + Vercel / Netlify
```

理由：

- Next.js 可以写服务端 API，隐藏 Notion Token
- 可以做漂亮的前端页面
- 部署方便
- 后续可以扩展缓存、详情页、统计页

如果想更轻量，也可以用：

```text
Astro + Serverless Function
```

但第一版建议 Next.js，生态更顺。

## 环境变量

网站需要这些环境变量：

```text
NOTION_TOKEN=你的 Notion Integration Token
NOTION_DATABASE_ID=你的微信读书 Notion 数据库 ID
```

可选：

```text
SITE_TITLE=我的微信读书书架
SITE_DESCRIPTION=从微信读书同步而来的个人阅读记录
```

## 数据读取流程

### API 路由

网站提供一个服务端接口：

```text
GET /api/books
```

这个接口做几件事：

1. 读取环境变量里的 `NOTION_TOKEN`
2. 查询 Notion 数据库
3. 把 Notion 的复杂字段转换成简单 JSON
4. 返回给前端

返回结构建议：

```json
[
  {
    "id": "notion-page-id",
    "title": "红楼梦",
    "author": "曹雪芹",
    "cover": "https://...",
    "status": "读完",
    "progress": 1,
    "readingTime": "12时30分",
    "categories": ["文学", "古典小说"],
    "highlightCount": 42,
    "thoughtCount": 8,
    "wereadUrl": "https://weread.qq.com/..."
  }
]
```

### 排序

默认排序：

```text
Sort 降序
```

也就是最近更新的书排前面。

前端可以支持：

- 最近更新
- 阅读进度
- 划线数量
- 书名

## 页面设计

### 首页：阅读书架

首页是核心页面。

布局：

```text
顶部个人标题区
统计概览
筛选工具栏
书籍卡片网格
```

首屏建议展示：

- 标题：微信读书书架
- 副标题：记录从微信读书同步而来的阅读、划线和想法
- 统计：
  - 总书数
  - 已读完
  - 在读
  - 总划线数

书籍卡片显示：

- 封面
- 书名
- 作者
- 状态 badge
- 阅读进度条
- 分类标签
- 划线数 / 想法数

### 筛选和搜索

第一版建议支持：

- 按书名搜索
- 按作者搜索
- 按状态筛选：全部 / 在读 / 读完 / 未读
- 按分类筛选

### 书籍详情页

第一版可以先做轻量详情页：

```text
/books/[id]
```

展示：

- 大封面
- 书名
- 作者
- 阅读状态
- 阅读进度
- 分类
- 划线数量
- 想法数量
- 跳转微信读书按钮

是否展示具体划线，建议做成可选配置。

原因：划线和想法可能包含私人内容。

## 视觉风格

建议做成“安静、清爽、阅读感”的个人站，不要太像后台管理系统。

方向：

- 深色 / 浅色都支持
- 卡片圆角克制
- 封面是第一视觉重点
- 标签颜色温和
- 进度条清晰但不抢眼

页面气质参考：

```text
个人阅读档案
私人图书馆
数字书架
```

## 缓存策略

Notion API 不适合每次页面访问都实时查询。

建议第一版做简单缓存：

- 服务端缓存 5 到 30 分钟
- 手动刷新时再请求 Notion
- 访问网站时优先返回缓存

如果部署到 Vercel，可以使用 Next.js 的 `revalidate`。

如果部署到 Netlify，可以用函数缓存或后续接 Netlify Blobs。

## 隐私策略

建议默认公开：

- 书籍基础信息
- 阅读状态
- 阅读进度
- 分类
- 统计数量

默认不公开：

- 具体划线
- 具体想法
- 书评正文

后续可以增加配置：

```text
PUBLIC_NOTES=false
```

只有设置成 `true` 时，才公开划线和想法。

## 第一版开发范围

建议第一版只做这些：

- 首页书架
- 搜索
- 状态筛选
- 分类筛选
- 阅读进度条
- 基础统计
- 跳转 Notion 或微信读书
- 服务端读取 Notion
- 不公开具体划线内容

不做：

- 登录系统
- 多用户
- 评论
- 后台管理
- 完整数据库

## 最小可行版本

MVP 可以非常简单：

```text
一个首页 + 一个 /api/books
```

只要能从 Notion 读出数据，并展示成漂亮的书籍卡片，就已经成立。

第一版目标不是复杂，而是：

```text
比 Notion 更适合公开展示，比数据库项目更容易维护。
```
